# onemove-churn-agent

원무브 회원 이탈 위험 감지 & 대응 에이전트. 설계 배경은 `naver-rank-tracker` 저장소의
`docs/churn-risk-agent-design.md` 참고.

## 진행 단계

- [x] 1단계 — 장난감 예제 (`01-toy-example.js`): 가짜 회원 데이터로 "도구함 + 목표 → AI가 스스로
  판단"하는 에이전트 루프를 확인
- [x] 2단계 — 읽기 전용 도구를 진짜 원무브 데이터에 연결 (`02-real-data-readonly.js`): 실제
  API로 첫 실행 성공 (2026-08-19). `recentVisits`/`avgVisits` 같은 단순 필드가 실제 API엔 없어서,
  AI가 `joinedAt`/`attendedAt`/패스 유효기간(`startedAt`~`endedAt`)을 스스로 비교하는 방식으로
  판단 기준을 즉석에서 만들어냄 — 하드코딩된 로직이 아니라는 걸 실데이터로 확인.

  **실행 노트**: 첫 실행에서 `noVisitsPeriod=14` 후보가 전부 "체험권만 받고 정식 등록 안 한
  사람"이었음 (일주일 체험권 등). 이건 "이탈"이 아니라 "체험 미전환"이라 성격이 다름 → 시스템
  프롬프트/도구 설명에 "정식(비체험) 계약 이력이 있는 회원만 대상"으로 필터링 지시 추가함.
  체험 미전환자 팔로업은 추후 별도 과제로 분리 고려. 또한 `flag_risky_member`에 `reason` 필드가
  누락된 채 호출된 사례가 있어 `strict: true`로 필수값 강제 처리함.

  `/members` 응답이 페이지네이션되어 있어(total 282, 페이지당 15) 처음엔 첫 페이지만 보고 있었음
  → `reservationApi.js`에서 offset을 늘려가며 끝까지 모아오도록 수정. 282명 전체를 검토하면서
  생각(thinking)에 토큰을 많이 써서 `max_tokens` 8000에서 응답 없이 끊기는 문제 발생 →
  스트리밍 + `max_tokens: 16000` + `effort: "medium"`으로 해결.

  282명 전체 실행 결과(1차): 158명 체험 미전환(제외), 80명 신고, 20명은 "레뷰 체험단" 패스라 AI가
  스스로 판단 보류(강석 확인 요청) — **데이터에 없는 걸 추측하지 않고 사람에게 물어본 좋은 사례**.
  확인 결과: 레뷰체험단은 기간이 2주면 최초 신청 시 발급되는 체험용(제외), 3개월권처럼 길면
  정식 유료 회원(포함)이라는 규칙 확인 → 프롬프트에 반영. 또한 80명이 "패스 유효기간 남았는데
  안 옴(지금 잡아야 함)"부터 "10개월 전에 이미 떠남(사실상 이탈 완료)"까지 긴급도가 섞여 있어
  실무에서 우선순위 판단이 안 됨 → `flag_risky_member`에 `risk_level`(high/medium/low) 필드
  추가해서 긴급도별로 구분되게 함.

  **282명 전체 실행 결과(2차)**: risk_level 반영 후 재실행. 총 103명 신고 (high 33 / medium 17 /
  low 53), 체험 미전환 179명 제외. 레뷰체험단 규칙도 정확히 적용됨(117일 '레뷰연계'는 정식 포함,
  14~20일짜리는 체험 제외). 애매한 케이스(예: 패스가 아직 시작 전인 state 0 회원)도 근거를 들어
  스스로 medium으로 분류하고 요약에 설명함.

  강석 피드백: '코치수강권'은 코치(직원)용이라 완전 제외돼야 하고, '엠버서더 전용'/'양도'
  같은 특수 패스는 AI가 좀 더 판단해줬으면 함 → 프롬프트에 반영.

  **282명 전체 실행 결과(3차, 최종 — 2026-08-19)**: 코치수강권 보유자 3명(김지훈/권준학/이기현)
  완전 제외 확인. 엠버서더 전용(8명)/양도(4명)는 신고하되 각 reason에 "유료 고객 관계 확신 낮음,
  컨택 전 결제 이력 확인 필요"를 명시 — 요청한 수준의 판단이 정확히 구현됨. 덤으로 AI가
  `noVisitsPeriod` 후보 중 실제로는 최근 14일 내 `attendedAt`이 있는 28명을 스스로 재검증해서
  오탐으로 제외함 (API 필터만 믿지 않고 실제 필드로 교차검증). 최종: 총 78명 신고
  (high 17 / medium 13 / low 48).

  강석 요청: 수강권-결제내역 대조, 홀딩(휴회) 여부 판단 추가 → `get_transactions_by_month` 도구
  추가, 홀딩 필드는 데이터에서 직접 찾아보고 없으면 솔직히 보고하도록 지시.

  **282명 전체 실행 결과(4차)**: 결제내역 대조로 "엠버서더 전용 = 0원 무상 등록"이라는 실제 근거
  확보, 홀딩 전용 필드는 못 찾았다고 정직하게 보고(추측으로 제외하지 않음). 하지만 신고 인원이
  78→99명으로 튐 — 원인 확인 결과 **AI가 "오늘 날짜"를 몰라서 데이터 안 최근 attendedAt을 오늘로
  착각**, 실행마다 판단이 오락가락하던 버그였음 → `todayStr()`로 실제 오늘 날짜(KST)를 프롬프트에
  직접 주입해서 해결. 또한 결제내역에서 BONG이 트레이너(직원)로 등장하는 걸 발견 → 강석 확인:
  코치수강권처럼 완전 제외 규칙 적용하기로 함.

  **비용 이슈**: 282명 전체를 여러 번 반복 실행하면서 토큰 사용량이 빠르게 늘어남 — 매 턴 전체
  대화(282명 데이터 포함)를 통째로 재전송하는 구조가 원인. 대응: (1) `cache_control`로 프롬프트
  캐싱 활성화, (2) 턴마다 토큰 사용량 로그 추가, (3) 개발 중 `TEST_MEMBER_LIMIT` 환경변수로 후보
  수를 줄여 저렴하게 테스트 가능하게 함, (4) 모델을 `claude-opus-5`에서 `claude-sonnet-5`로 변경
  (강석 확인 — 최종 검증 시 필요하면 opus로 다시 바꿀 수 있음).

  **다음에 재검증할 것**: 오늘 날짜 버그 수정 + BONG 제외 규칙 반영 후 282명 전체로 최종 1회 더
  돌려서 결과 확정할 것 — 3단계(메시지 초안 생성)로 넘어가기 전 마지막 확인.

  강석 피드백: "결과가 알아보기 쉽게 나와야 한다"는 방향만 주고 구체적 형태는 안 정했는데, 확인
  없이 CSV로 바로 구현해버림 → 이 피드백 자체로 `CLAUDE.md`에 "방향만 받았을 때 먼저 확인 질문할
  것" 지침 추가. 이후 다시 질문해서 확정: 결과는 CSV 대신(추가로) **슬랙 메시지로 바로 전송**,
  분량은 "요약 + high 등급 전체 명단"으로. `lib/slack.js` 추가(naver-rank-tracker의
  reporter/slack.js와 동일한 Incoming Webhook 패턴). `SLACK_WEBHOOK_URL` 설정 필요.

## 실행 방법 (로컬, 맥)

```bash
cd onemove-churn-agent
npm install
cp .env.example .env   # .env에 본인 ANTHROPIC_API_KEY 채워넣기 (2단계부터는 RESERVATION_* 값도)
npm run toy      # 1단계: 가짜 데이터
npm run step2    # 2단계: 진짜 원무브 데이터 (읽기 전용, 반드시 맥에서 실행)

# 프롬프트만 다듬어보는 개발 중에는 후보 수를 줄여서 싸고 빠르게 테스트:
TEST_MEMBER_LIMIT=20 npm run step2
# 최종 확인할 때는 TEST_MEMBER_LIMIT 없이(=282명 전체) 돌릴 것
```

실행이 끝나면 `output/이탈위험목록_YYYY-MM-DD.csv` 파일이 생성됩니다 — 위험도/회원/판단 근거가
표로 정리되어 있어 엑셀·넘버스로 바로 열어볼 수 있습니다. 실제 회원 이름이 담기는 파일이라
`.gitignore`에 등록해 깃에는 올라가지 않습니다.

**슬랙 요약도 함께 전송됩니다** — `.env`에 `SLACK_WEBHOOK_URL`을 채워두면, 실행 끝에 위험도별
인원수 + high 등급 전체 명단(이름+판단 근거)을 슬랙으로 바로 보내줍니다. medium/low 전체 명단은
CSV 파일에서 확인. 웹훅 URL이 없으면 이 단계는 건너뛰고 경고만 출력됩니다(CSV는 정상 저장).

## 참고

- 1단계는 어디서든 실행 가능하지만, 2단계부터는 원무브 예약 API(`api-reservation.onemove.co.kr`)에
  접속해야 해서 반드시 로컬 Claude Code(맥)에서 실행 — Cowork/클라우드 세션은 해당 도메인이
  allowlist에 없어 직접 호출이 막혀 있습니다 (`onemove-reservation-api` 스킬 참고).
- `RESERVATION_API_USERNAME`/`PASSWORD` 값은 기존 `onemove-crm-agent/.env` 또는
  `onemove-daily-report/.env`에 이미 있는 값을 그대로 복사해서 씁니다.
